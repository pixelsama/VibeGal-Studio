# Review 28 — 产品现状评审与开发路线图

> 状态：路线图已确认；P0 与 P1 已完成，P2–P4 已分别固化为 [Spec 30](./30-facade.spec.md)、[Spec 31](./31-genre-capabilities.spec.md) 与 [Spec 32](./32-scale-and-distribution.spec.md)，正在实施 P2。
> 日期：2026-07-26。
> 方法：通读仓库 + 实际运行 `pnpm tauri dev`（示例项目 `examples/sample-novel`）逐工作台截图，
> 并对照 `title-preview/` 的默认渲染层快照。全量测试通过（vitest 852 + node:test 19）。

## 0. 一句话结论

**数据契约和工程底座是这个项目最强的部分（可以直接进 beta），创作者面前的那一层是最弱的部分。**
三个断层按严重度排序：

1. **写作主界面在参数一偏离默认值时退化成 JSON**（剧本编辑器的「JSON 悬崖」）；
2. **默认渲染层是"能跑的占位"而不是"能发布的成品"**，且标题画面存在确定性 bug；
3. **界面语言仍在三套词汇之间漂移**（创作者语 / 工程语 / 英文），外观工作台本身就是一个 CSS Inspector。

Spec 24 → 26 → 27 这条线（故事状态从"分析报告"变成"创作对象"）方向是对的，也确实落地了。
问题是同样的病还留在**剧本编辑器、外观工作台、资产工作台、默认渲染层**四个地方，只是还没轮到它们。

## 1. 外观评审

### 1.1 Studio 自身

判断：**需要优化，但不需要推翻。** token 体系（`index.css` 的 radius/space/text/control 四组）
已经建好了，深浅两套色板齐全，问题出在**应用层没有把 token 用出层次**。

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| A1 | 页面没有"分区"感，所有内容都是一列表单浮在大片留白上 | 项目工作台：5 个字段占满 1280×800，剩下 70% 空白 | 看起来像半成品，也浪费了大屏 |
| A2 | 中英混排 | `Inspector`（脚本右栏）、`CG Gallery`（渲染层菜单）、`Cleanup dry-run`、`manifest`、`--strict`、`fade_in`、`default` | 破坏"面向创作者"的定位 |
| A3 | 同一个东西三个名字 | 顶栏「界面风格」/ 信任提示「renderer」/ 导出页「渲染层」；插入面板「变量」vs 已改名的「故事状态」 | 用户学不会自己在用什么 |
| A4 | 密度失衡 | 图画布上下大片空白但 minimap 占 300×230 且无法关闭；右侧 Inspector 空态仍占 340px | 主对象（画布）被辅助件挤压 |
| A5 | 危险操作常驻 | 资产每张卡都有红色「删除」（9 张卡 9 个红按钮）；章节行常驻红色垃圾桶 | 视觉噪音 + 误触风险（确认弹窗有，但视觉上先吓人） |
| A6 | 标签比值更弱 | 表单 label 用 `--text-muted`，值用 `--text-primary`，label 看起来像禁用态 | 扫读时找不到字段名 |
| A7 | 长标识中间断行 | 信任页把路径断成 `…/examples/sa` + `mple-novel`；Brief 25 记录过 `playthroughCo/unt` | 同一个 CSS 缺陷（缺 `word-break` 策略）反复出现 |
| A8 | 强调色只有一个蓝 | 主按钮 / 选中 tab / 链接 / 焦点环同色 | 没有产品识别度，也分不出"主操作 vs 当前位置" |
| A9 | 空态只有一行灰字 | 「选择一个节点查看属性」「项目正常」 | 新用户不知道下一步做什么 |

### 1.2 默认渲染层（玩家看到的画面）

判断：**需要重做一轮，这是产品的门面。** 现在这套是"验证契约用的样式"，不是"作者敢直接发布的样式"。

- **标题画面**：一个居中的灰白圆角卡片 + 粉色标题 + 4 个等宽白色胶囊。它更像一个设置对话框，
  不像 galgame 标题画面（缺 logo 位、缺立绘/CG 主视觉、菜单没有排版重心）。
- **禁用态几乎不可见**：「继续游戏 / 读取存档」灰到看不清，玩家会以为界面坏了。
- **HUD**：`菜单 快存 快读 自动 OFF 已读跳过 OFF 全文跳过 OFF 历史` 一行 7 项，用 "OFF" 后缀表示
  状态——这是开关的**技术表示法**，galgame 惯例是高亮/变色。
- **选项按钮和标题菜单按钮同一套样式**，都是浅灰胶囊，浮在角色立绘中央，对比度低。
- **左下角常驻 `3/10`**：调试样式的进度指示漏进了玩家画面。
- **菜单窗口是浅色**，与深色场景割裂；侧栏 `MENU` 用拉丁字母 + `CG Gallery` 英文，其余中文。
- **设置面板暴露 `30 CPS` / `1200 ms`**，并且要点「应用设置」才生效（galgame 惯例是即时生效）。
- **场景快照里存档页显示 `player_ui_busy 另一项存档操作正在进行中。`**——fixture 把错误态当默认态截了。

## 2. 交互评审

### 2.1 剧本编辑器的「JSON 悬崖」（最高优先级）

`formatScenarioInstruction()`（`packages/engine/src/scenario.ts:232`）的策略是：先生成可读语法，
再 parse 回来比对，**不等价就整条降级成 `@instruction {…JSON…}`**。而可读语法是**有损**的：

| 指令 | 可读语法能表达 | 写死的默认值 | 于是什么情况会变 JSON |
|---|---|---|---|
| `@bg` | id、trans | `ms: 1000` | 任何自定义淡入时长 |
| `@char` | id、expr、pos | `ms:600, clear:false, remove:false` | **角色退场 / 清场**（galgame 高频操作） |
| `@bgm` | id | `fade:1500, loop:true` | 单次播放、自定义淡入 |
| `@effect` | type | `intensity:6, ms:400` | 任何强弱调整 |
| `@transition` | type | `ms:1000` | 任何非 1 秒转场 |

实测：示例项目「苏醒」节点的**第一行**就是
`@instruction {"ms":1200,"t":"transition","type":"fade_in"}`——作者打开自己的剧本，第一眼看到 JSON。

雪上加霜的是右侧表单：转场只给了「类型」下拉，下面直接写着
**「时长参数请切到 JSON」**。也就是说产品自己承认表单编辑器不完整，并把用户推回 JSON。

这一条不修，"低门槛创作工具"的承诺就是空的。

### 2.2 预览 / 试演

- 工具条上两个下拉**没有可见标签**（只有 `aria-label`）：作者看到「序章 ▾」「节点开头 ▾」，
  不知道它们是"从哪里开始试演"。
- Studio 侧**没有播放控制**（重新开始 / 后退一句 / 自动 / 快进）。这些能力在引擎里有
  （`controls` / 回滚 / skip），但只暴露在渲染层 HUD 里——换一个渲染层就可能全没了。
- Spec 26 把「假设前情 → 从这里试演 → 剧情检查」的时间关系理顺了，方向正确。剩下的问题是
  **入口密度**：一行里塞了 2 个下拉 + 3 个按钮 + 2 个模式 tab。
- 节点编辑器右侧的预览**默认停在标题画面**，而不是当前节点——作者要多点一次「从当前行」。

### 2.3 图编辑

- 边上直接画原始表达式（画布上能看到 `e >= 3 && knows_…` 被截断）。故事状态视图已经句子化了，
  画布还没跟上。
- 节点卡上显示 `nodes/approach.json` 文件名和 `↑1 ↓2` 入/出度——工程信息占了卡片一半。
- 「重置视图 / 自动排布」只在右键菜单里，工具条上没有。
- 撤销/重做叠在左下角 React Flow 控件列里，和缩放按钮混在一起。

### 2.4 资产

- **总览页没有导入入口**——新用户落在总览，无法添加素材（导入按钮在具体分类页）。
- 同一个清理操作有两个按钮，上下两行：右上「清理 2 个悬空引用」+ 横幅「确认清理 manifest」。
- 卡片副标题 `manifest 1 / 剧本 2` 是引用计数，但没有任何说明。

### 2.5 其他

- **渲染层信任是内存态**（`rendererTrust.ts` 用 `new Set()`），每次启动应用、每次改 renderer
  都要重新点一次「信任并运行项目 renderer」。而且这个页面用的是 `renderer` 这个词。
- **打开项目会写项目文件**：打开 `examples/sample-novel` 后自动生成了
  `.galstudio/schemas/variables.json`（仓库里没有这个文件）。对把项目放进 git 的用户来说，
  "只是看一眼"就产生 diff。
- **没有 onboarding**：新建项目后没有"接下来做什么"的引导；空态教学只在故事状态页有。
- 起始页把「最近打开」和「工作区」两份列表堆在一起，同一个项目出现两次；显示的是绝对路径 +
  绝对时间，没有封面、没有搜索、没有置顶。

## 3. 功能评审

### 3.1 确认的缺陷

| # | 缺陷 | 位置 | 严重度 |
|---|---|---|---|
| B1 | **游戏标题永远显示「未命名作品」** | `templates/default-renderer/TitleScreen.tsx:35` 读 `manifest.name`，但 `ManifestSchema` 是 `strictObject` 且**没有 name 字段**；标题真正存在 `content/meta.json.title`，而 `RendererProps` 只传 `stage`，不传 `meta.title` | **高**：每个导出的游戏标题都是错的，且作者在「项目 → 项目标题」里改了也没用 |
| B2 | 同一个项目三个名字并存 | 顶栏显示 `gal.project.json.name`（"野生舰娘 · 序章"），项目页显示 `meta.title`（"兵装心智体 · 序章"），标题画面显示"未命名作品" | 中：作者不知道哪个是"作品名" |
| B3 | 剧本编辑器降级 JSON | §2.1 | **高** |
| B4 | 表单编辑器不完整并把用户推回 JSON | `NodeInspector` 转场只能改类型 | 高 |
| B5 | Web 导出在 Studio 里消失了 | `ExportWorkspace` 只有 `导出桌面游戏`；`build --target web` 只在 CLI 里。README「快速开始」仍写"构建 Web 游戏或桌面游戏" | 中：web 是同人作者最常用的分发方式（itch.io / 网页 demo） |
| B6 | 打开项目产生文件写入 | §2.5 | 低—中 |
| B7 | 高级选项直接暴露 CLI flag | 导出页「严格模式（--strict）」「允许警告（--allow-warnings）」 | 低 |

### 3.2 galgame 品类能力盘点

已有（质量不错）：图优先剧情、章节、条件分流、出口效果、故事状态（flag/meter/state/counter/text +
分段/枚举/范围钳制）、结局登记与结算、存读档、历史回看、CG/音乐/回想/结局四类解锁、
自动/跳过/已读跳过、视频、转场与画面效果、舞台分辨率、外观 token、渲染层热重载、
项目校验 + CLI + JSON Schema + 稳定指令 ID。

**明显缺口**（按 galgame 常见需求排序）：

1. **本地化 / 多语言**——契约里完全没有 locale 概念，文本硬编码在 `say.text` / `narrate.text`。
   一旦有项目开始翻译，这是**破坏性契约变更**，越晚做越贵。
2. **逐行语音绑定**——`voice` 是独立指令，作者要手工在每句台词前插一条。行业惯例是
   `say` 自带 `voice` 字段，或按 story-point id 自动查表。
3. **文本装饰**——没有 ruby（注音）、行内变色/加粗、行内停顿、变量插值（`{雪.好感度}`）、
   玩家命名输入。变量插值和玩家命名是 galgame 的基本盘。
4. **立绘表现力**——`char` 只有 pos（语义槽）+ expr，没有移动、缩放、翻转、抖动、
   表情过渡；没有 Live2D/Spine 接入点（`animationAtlases` 有位置但没有运行时语义）。
5. **存档体验**——没有存档缩略图、没有存档页数扩展、没有"章节回想/跳读"入口。
6. **发布元数据**——导出物没有图标、版本号、公司名、窗口标题的设置入口。

### 3.3 工程健康度

- 测试：871 个用例全绿；CI 覆盖 frontend/CLI/Rust/schema drift/engine types/renderer template/版本一致性。**很好。**
- 契约单一来源（zod → types → JSON Schema → Rust validator）+ 版本/修订冲突模型 + 路径安全 + 原生 watcher。**很好。**
- 已知短板：
  - 无任何列表虚拟化（资产网格、节点列表、章节列表），大项目会卡；
  - `AssetsWorkspace.tsx` 1487 行 / `ExportWorkspace.tsx` 1249 行 / `ScriptWorkspace.tsx` 1049 行，
    单文件承担了状态机 + 布局 + 弹窗 + 持久化；
  - 大量内联 `CSSProperties` 与 `.gs-*` class 并存，token 收敛只做了一半（`index.css` 注释里
    写了"P3 逐步收敛"）；
  - 没有 i18n 层，全部中文硬编码——同时挡住了 §3.2.1 的作品本地化和 Studio 自身的英文版。

## 4. 路线图

原则：**先补断层（用户已经会撞上的），再补品类能力（用户接下来会要的），最后做规模化。**
每一阶段都能独立发一个版本。

### P0 — 修断层（目标 0.1.0-alpha.2，约 1–2 周）

只做"现在就错了"的事，不引入新概念。

1. **修标题链路（B1/B2）**
   - `RendererProps` 增加 `meta`（或至少 `title`），`TitleScreen` 改读它；
   - 确定唯一的"作品名"来源（建议 `meta.title` 为准，`gal.project.json.name` 降级为文件夹标识），
     项目页说明二者关系；
   - 回归测试锁定"改了项目标题 → 标题画面和导出物同时变"。
2. **剧本语法补全（B3 第一刀）**——让可读语法能表达全部常用参数，把 JSON 降级压到罕见分支：
   - `@bg id trans 1200ms`、`@char id expr pos out/clear`、`@bgm id once`、
     `@effect shake 8 400ms`、`@transition fade_in 1200ms`；
   - 保持"无法表达就降级 JSON"这个兜底不变（它本身是对的），但让它真的成为兜底。
3. **表单补全（B4）**：`NodeInspector` 把转场/效果/背景/角色的全部参数做成控件，删掉
   「请切到 JSON」这句话。
4. **Web 导出回到 Studio（B5）**：导出页加「Web / 桌面」目标切换，复用现有 preflight 与 buildStore。
5. **信任状态持久化**：按项目路径 + renderer 内容指纹记住信任，内容变化时重新询问；
   文案里把 `renderer` 改成「界面风格」。
6. **打开项目不写盘（B6）**：schema 同步改为"缺失时提示 + 一键补齐"，或写进应用缓存目录。
7. **词汇表落地**：建 `docs/vocabulary.md`（界面风格 / 故事状态 / 分流 / 出口效果 …），
   清掉 `Inspector`、`CG Gallery`、`Cleanup dry-run`、`--strict`、`fade_in` 等技术串；
   加 `check:vocabulary` 脚本挡回归。

### P1 — 写作主循环（0.2.0，已于 2026-07-27 完成）

让“写一段剧情”这条路径从头到尾不掉出去。以下能力均已落地，详细契约与验收见 [Spec 29](./29-writing-loop.spec.md)：

1. **剧本编辑器二期**：语法高亮（说话人/指令/状态改变分色）、角色与资源 id 自动补全、
   指令行内可视化控件（点一下就能改时长/表情，不必记语法）、拖拽调序。
2. **节点编辑器预览默认从当前节点开始**，并提供"跟随光标"开关。
3. **Studio 级播放控制**：重新开始 / 上一句 / 下一句 / 自动 / 快进，做在预览工具条上，
   不依赖渲染层 HUD。
4. **画布句子化**：边标签显示句子化条件（复用 `storyState.ts` 的解释器），
   节点卡去掉文件名与入出度，改为"台词数 / 有无状态改变 / 是否结局"。
5. **资产总览可导入**（拖拽 + 按钮），合并两个清理入口，引用计数加说明。
6. **空态与 onboarding**：新建项目后给三步引导（写第一个节点 → 导入一张背景 → 试演）；
   每个工作台的空态给一句"这里能做什么" + 一个主操作。
7. **示例项目独立成模板**（Spec 26 §1 已定的分工），新建项目时可选"空白 / 带示例"。

### P2 — 门面（0.3.0，已于 2026-07-27 完成）

详细数据边界、验收矩阵与提交顺序见 [Spec 30](./30-facade.spec.md)。

1. **默认渲染层重做**：标题画面（logo 位 + 主视觉 + 菜单排版）、选项按钮（区别于菜单按钮）、
   HUD（图标 + 高亮态，去掉 `OFF` 后缀）、菜单窗口（与场景同色系）、去掉 `3/10` 调试指示、
   设置项换成创作者/玩家语言并即时生效。
2. **外观工作台从 CSS Inspector 变成设计工具**：预设主题（3–5 套）→ 微调；
   颜色控件显示真实默认色（现在色块一律是黑的）；每个字段可"恢复默认"；
   直接在画布上拖拽/缩放，数值面板收进"高级"。
3. **Studio 视觉第二版**：面板层次（卡片/分区/分隔）、标签与值的对比度反转、
   宽屏下的双列布局（项目页/设置页不再是一列孤字段）、长标识断行策略统一、
   第二强调色区分"当前位置"与"主操作"。
4. **多套渲染层模板**：至少再给一套风格（例如经典深色 ADV），证明 renderer 契约的价值。

### P3 — 品类能力（目标 0.4.0，待 P2 收口）

详细兼容契约、运行时语义、验收矩阵与提交顺序见 [Spec 31](./31-genre-capabilities.spec.md)。

按"越晚做越贵"排序，本地化排第一。

1. **本地化契约**：`say.text`/`narrate.text` 支持 key + locale 表（新增 `content/locales/*.json`），
   Studio 提供翻译对照视图，CLI 提供缺失翻译报告。**这是破坏性变更，越早定越好。**
2. **逐行语音**：`say` 增加可选 `voice`；或约定"story-point id ↔ 语音文件名"自动绑定 + 缺失报告。
3. **文本能力**：变量插值 `{雪.好感度}`、玩家命名输入、行内停顿/变色、ruby。
4. **立绘表现**：move/scale/flip、表情过渡时长、`animationAtlases` 的运行时语义。
5. **存档体验**：缩略图、更多槽位、章节跳读/回想入口。

### P4 — 规模与分发（目标 1.0，待 P3 收口）
